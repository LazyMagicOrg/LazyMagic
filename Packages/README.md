# `Packages/` — LazyMagic's local NuGet feed

This folder holds the `.nupkg` files this repo builds: the `LazyMagic.*` family. They are **build output** —
generated by `GeneratePackageOnBuild` plus the `CopyPackage` target, consumed locally by
Service, BaseAppLib and the Lz project templates, and never hand-edited or committed.

## Why this README is tracked

**So the folder exists on a fresh clone.** The workspace `Nuget.Config` names this path as a
`packageSource`, and NuGet does not treat a configured-but-missing local source as an empty feed —
it fails the restore outright:

```
error NU1301: The local source '...\Packages' doesn't exist.
```

Restore runs before any build target, so nothing in the build can create the folder in time. The
first build of a fresh clone simply fails. Git tracks files rather than directories, so the folder
needs one tracked file inside it, and a README is more use than an empty `.gitkeep` — it tells
whoever finds an apparently-pointless file why deleting it breaks the build.

Everything else here is ignored; see this repo's `.gitignore`.

## One feed per producer

Each producing repo writes into its own `$(SolutionDir)Packages`. Until 2026-09-08 Service and
BaseAppLib shared a single `repos/Packages` at the workspace root; splitting them retired the hazard
that neither could publish with a `./Packages/*.nupkg` glob without pushing the other's packages
under its own name. See `repos/Docs/specs/PerProducerPackages.md`.
